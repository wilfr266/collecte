# Règles du projet TERENZA

- Préserver les plateformes et données existantes; aucune suppression destructive sans justification et autorisation.
- Garder le code Dart typé, formaté et organisé par fonctionnalité.
- Ne jamais présenter des exemples comme des données réelles ni une maquette comme une intégration opérationnelle.
- Ne jamais embarquer de secret privilégié dans Flutter; les permissions sensibles sont validées côté serveur.
- Ajouter des tests pour les règles métier et les parcours modifiés.
- Avant une migration distante, vérifier le projet cible, examiner le SQL et obtenir une validation explicite.
- Documenter les décisions, les limites de validation et les étapes manuelles.
